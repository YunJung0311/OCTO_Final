## 1. 경험 설계

```
[대기]                    [말하기 시작]                 [말하는 중]
배경색 전체                얼굴이 계단식으로 축소        얼굴(작게, 위)
얼굴 크게                  + 위로 이동                   ┌──────────┐
                           (4프레임, 스텝 애니)          │ 자막 ▼    │  ← 말풍선, 꼬리는 얼굴 쪽
                                                         └──────────┘
[말 끝남] turnComplete + 오디오 재생 종료 + 1.2초 유지 → 말풍선 닫힘 → 얼굴 원위치
[끼어들기] interrupted → 말풍선 즉시 닫힘
```

- 얼굴은 위로 올리고 말풍선은 아래가 기본 (하단 자막 관습 + 꼬리가 위로 얼굴을 가리킴). 캐릭터별로 반대로 할 수 있게 옵션.
- 움직임은 모두 **스텝(계단) 애니메이션**. 부드러운 tween은 도트 경계가 뭉개져서 픽셀 감성이 깨짐. CSS `steps(4)` 또는 JS에서 dot 단위로 스냅.
- 말풍선 등장: RPG 대화창처럼 위아래로 한 줄씩 열리는 reveal, 또는 2단계 팝(작게 → 원래). 
- 자막 길이가 넘치면 스크롤 대신 **페이지 넘김** + 우하단 깜빡이는 `▼` (참고 이미지 3의 RPG 감성).

### 일본어·중국어 폴백
- `@font-face`의 `unicode-range`로 한자·가나 범위만 Fusion이 받도록 지정.
- 문제: 한글 서체는 16px 그리드, Fusion은 12px 그리드. 같은 `font-size`를 받으면 Fusion이 1.333배로 확대돼 흐려짐.
- 해결: Fusion `@font-face`에 **`size-adjust: 75%`**. 그러면 16d px 안에서 Fusion이 정확히 12d px로 렌더링돼 둘 다 선명. 세로 위치가 1~2px 어긋나면 `ascent-override`로 맞춤.
- 쓸 파일: Fusion 릴리스의 `12px proportional` woff2 (ja, zh_hans 각각 또는 통합본).

## 3. 픽셀 비율 시스템 (rem을 쓰면 안 되는 이유와 대안)

### 원리
- 도트 서체는 "서체의 1픽셀 = 화면의 정수 픽셀"일 때만 선명함. 16px 서체를 16, 32, 48px로 쓰면 깨끗하고, 20px나 1.2rem으로 쓰면 픽셀 가장자리가 반투명하게 번짐.
- Pi의 Chromium(리눅스)은 CSS로 안티앨리어싱을 끌 수 없음 (`-webkit-font-smoothing`은 맥 전용). 그래서 **정수 배율로 맞추는 것 자체가 유일한 선명도 확보 수단.**
- Chromium은 이미 `--force-device-scale-factor=1`로 켜지고 있어서 CSS px = 물리 px. 좋은 조건.

### 단위 하나로 전부 묶기: `d` (dot)
```
d   = 화면 1도트가 차지하는 물리 픽셀 수 (정수)
N   = 서체 기본 그리드 (16 또는 12)

font-size        = N × d
line-height      = (N + 2) × d        // 행간 2도트
말풍선 외곽선     = 1d (이중 테두리면 1d + 1d 간격 + 1d)
모서리 계단       = 1d 단위로 2~3칸
그림자 오프셋     = 1d (텍스트), 2d (말풍선)
padding          = 2d ~ 3d
```
- `d`는 JS가 실제 화면 크기에서 계산해 CSS 변수 `--d`로 내려줌. 모든 치수는 `calc(var(--d) * n)`.
- 얼굴 그래픽 축소 배율도 가능하면 정수비 또는 1/2, 1/3 같은 단순비로 스냅 (Canvas는 `image-rendering: pixelated`, SVG는 `shape-rendering: crispEdges`).

### 해상도별 시뮬레이션 (16px 서체, 좌우 여백 포함)
| 화면 | d=1 (16px 글자) | d=2 (32px 글자) |
| --- | --- | --- |
| 240×240 | 한 줄 약 13자, 4~5줄 | 한 줄 약 6자, 2줄 |
| 240×320 세로 | 한 줄 약 13자 | 한 줄 약 6자 |
| 320×240 가로 | 한 줄 약 18자 | 한 줄 약 8자 |
| 480×320 | 한 줄 약 28자 | 한 줄 약 13자 |

- 2인치 240px급이면 화면 밀도가 약 200ppi라 16px 글자는 실제 2mm 정도. 관람 거리에서 읽히는지 **실물로 한 번 봐야 함.** 아마 d=1(작지만 많이) vs d=2(크지만 6자) 사이에서 결정해야 할 것.
- 대안: 서체를 12px 그리드인 Fusion으로 통일하면 d=2에서 24px 글자, 한 줄 9자. 이건 "도스필기를 쓰고 싶다"와 충돌하므로 실물 확인 후 판단.

## 4. 말풍선 스타일

참고 이미지에서 뽑은 문법 세 가지:
1. **이중 테두리 + 계단 모서리 + 하드 드롭섀도** (이미지 1, 타이틀 박스)
2. **꼬리 달린 말풍선 + 바깥 흰 헤일로 + 겹친 그림자 레이어** (이미지 3)
3. **글자에 1도트 오프셋 그림자, 흐림 0** (이미지 2. 잉크 글자 아래 밝은 색 그림자)

구현 방식
- 말풍선은 **도트 격자 단위 SVG**로 생성 (`viewBox`를 도트 단위로 잡고 `d`배 확대, `crispEdges`). 크기는 자막 줄 수에 맞춰 JS가 격자 단위로 그림.
  CSS `border-radius`나 `box-shadow`로는 계단 모서리가 안 나옴.
- 텍스트는 그 위 HTML 레이어. `text-shadow: var(--d) var(--d) 0 <그림자색>`.
- 색은 캐릭터 팔레트에서 자동: 말풍선 채움 = 밝은색(흰/연한 배경색), 테두리·글자 = 각자의 잉크 컬러, 그림자 = 포인트 컬러. 구조는 하나, 색만 캐릭터별 → 전시장에서 "한 가족"으로 보임.
- 스타일 프리셋 2~3개(`box`, `bubble`, `rpg`)를 만들고 캐릭터별로 고르게.

## 5. 자막 타이밍과 줄넘김

### Gemini Live가 주는 것과 안 주는 것
- 주는 것: 오디오 조각(PCM)과 `outputTranscription` 텍스트 조각이 **같은 스트림에 섞여서** 순서대로 옴.
- 안 주는 것: 단어별 타임스탬프, "지금 몇 번째 문장 재생 중" 같은 정보. (알려진 범위에서 Live API 전사에는 타이밍 필드가 없음)
- 그리고 오디오는 실시간보다 빨리 도착해서 미리 예약 재생됨 → 텍스트가 말보다 앞서 도착함.

### 그래서 "지금 어디 말하는 중"은 우리가 계산함
재생 시간은 클라이언트가 이미 정확히 알고 있다. 오디오 조각마다 길이(바이트 수 / 24000Hz)와 예약 시작 시각(`playHead`)이 있으니까.

```
스트림:  [오디오 0.4s][오디오 0.4s][텍스트 "안녕 나는"][오디오 0.4s][텍스트 " 민서야"] ...
예약:    0.0────0.4────0.8         ↑ 이 시점 예약 끝 = 0.8s    1.2    ↑ = 1.2s
매핑:    "안녕 나는" → 0.0~0.8s 동안 한 글자씩 노출
         " 민서야"   → 0.8~1.2s 동안 한 글자씩 노출
```
- 텍스트 조각이 도착하면 "그때까지 예약된 오디오 끝 시각"을 붙여둔다 (앵커).
- 재생 시계(`AudioContext.currentTime`)가 앵커 사이를 지나가는 비율만큼 글자를 연다.
- 정확도는 조각 단위(대략 몇 어절)라서 입 모양 수준은 아니지만, 자막으로는 충분히 "말하는 만큼 나오는" 느낌. 전사가 오디오보다 늦게 오는 경우엔 앵커를 다음 오디오 조각에 붙이는 식으로 보정.
- 필요한 건 재생 함수(`playChunk` 등)를 한 번 감싸는 것뿐. 학생마다 함수 이름이 달라서 `project.py`의 STUDENTS 표에 함수 이름만 적어두면 됨. (헐은 이미 같은 원리로 입 모양을 동기화 중)
- 재생 함수를 못 찾는 캐릭터는 폴백: 한국어 TTS 평균 속도(약 6~7자/초)로 타자기.

### 줄넘김: 좌우 흐름보다 "한 줄씩 올라가는 롤업"
| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 좌우로 흐르는 전광판 | 한 줄이면 됨 | 한글은 흐르는 글자를 눈이 쫓기 어려움. 2인치에선 특히 피곤 |
| RPG 페이지 넘김 (▼) | 감성 최고 | 페이지 끝을 알아야 하는데 스트리밍이라 미래 텍스트를 모름 |
| **롤업 (2~3줄, 꽉 차면 1줄씩 위로)** | 스트리밍과 궁합 좋음. 지금 줄만 알면 됨 | 없음에 가까움. TV 생방송 자막과 같은 원리 |

- 추천: **롤업.** 줄이 차면 위 줄이 1줄 높이만큼 계단식(2~3프레임)으로 올라감.
- 줄바꿈 위치: 도트 서체는 글자 폭이 고정(한글 = 16d)이라 JS가 정확히 계산 가능. `word-break: keep-all`처럼 어절 단위로 끊고, 문장부호(. ? ! ~) 뒤에서는 우선 줄을 바꿈.
- 문장이 끝나고 다음 문장이 시작되면 말풍선을 비우고 새로 시작하는 옵션도 둠 (RPG 감성은 여기서 살림).

### 기타
- `interrupted` 처리: 현재 `octo-student.js`는 interrupted를 안 봄 → 자막 모듈에서 추가 (즉시 닫기).
- HYOSUN은 전사가 꺼져 있음 → 브리지가 setup 메시지에 `outputAudioTranscription: {}`를 주입하도록.

## 6. 구현 구조 (제안)

```
octo/bridge/octo-subtitle.js   ← 새 파일. 모든 학생 배포본에 주입
octo/bridge/subtitle-fonts/    ← woff2 5종 (+ Fusion ja/zh)
octo/project.py                ← STUDENTS 표에 캐릭터별 설정 추가
                                  { font, bubbleStyle, faceSelector, layout: "up"|"down" }
docs/subtitle/preview.html     ← API 없이 모의 텍스트로 돌려보는 디자인 미리보기
```
- `octo-subtitle.js`가 하는 일: ① `--d` 계산 ② 얼굴 요소를 감싸 축소·이동 ③ 말풍선 SVG 생성 ④ 전사 텍스트를 받아 타자기 + 페이지 넘김 ⑤ turnComplete / interrupted 처리.
- 학생 원본 `.sh`는 수정하지 않음 (기존 octo 방침과 동일).

## 8. 추천 진행 순서 (작게 한 바퀴부터)

1. **민서 1명 + 도스필기 + 말풍선 1종 + 모의 텍스트**로 `preview.html` 하나 완성. 실물 2인치 화면에 띄워서 글자 크기 판단.
2. 크기가 확정되면 `octo-subtitle.js`로 일반화하고 캐릭터별 색·서체 표 채우기.
3. 실제 Gemini 연결로 타이밍 확인 (민서).
4. 나머지 7명 적용, 배포 zip.

1번이 끝나기 전에는 스타일 프리셋을 늘리지 않는다. 첫 화면을 실물로 보기 전에 고른 디테일은 대부분 다시 바뀜.
